# Life Story Companion — Compatibility

**Current public status:** Premium Skill purchase is live ($49 one-time download). **No AI platform is advertised as officially supported yet.**

The Life Story Companion is designed as an **AI skill for use inside a compatible AI assistant**, not as a standalone assistant. The commercial package is **skills-only**: downloadable instructions/plugin files. C.B. Ventures does **not** run a hosted project database or MCP service as part of this product. Compatibility is validated platform by platform rather than assumed from the ability to paste instructions into a chat.

## What "supported" will mean

A platform will be listed as supported only after its adapter has been tested for the parts of the **skills-only** workflow that matter, including:

- installation and updates;
- interview behavior and instruction following;
- files and source handling on that host;
- helping the assistant keep project structure in the **host's own memory, project files, and exports** (not a C.B. Ventures server);
- transcript ingestion where the host allows it;
- provenance and uncertainty tracking;
- privacy/data boundaries of the **host** platform;
- known limitations (including limits of host memory/files).

The skill helps the buyer's AI persist useful context via the host's memory and files. That is **not** the same as Companion-owned cross-session storage. Host limits will be disclosed rather than hidden.

## Current validation track

An initial OpenAI plugin-format adapter has passed internal static package checks and is awaiting live installed-runtime testing for skills-only behavior.

An optional local MCP persistence prototype exists for internal/Desktop experiments. It is **buyer- or developer-local**, **not** a public Companion-hosted service, and **not** part of the skills-only SKU or a supported-platform claim.

The testing sequence is intentionally conservative:

1. validate the skill's activation and interviewing behavior;
2. validate file/source handling and evidence discipline on the host;
3. validate how the skill uses host memory/files for continuity, and disclose host limits;
4. publish a compatibility claim only after the exact supported **skills-only** configuration passes.

Any future hosted service, if ever offered separately, would require its own validation and disclosure—and would not rewrite what the skills-only SKU is.
